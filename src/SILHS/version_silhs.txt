    Add reusable case runners for timing (#1400)
    
    We have multiple entry points now for clubb standalone (fortran,python,jax), and there's additional logic that chooses which fortran installation to use (gfortran,ifort,nvhpc,etc). All of this has historically (~1 year) been done by run_scm.py, but we have a number of other scripts that need this same kind of logic, so instead of making run_scm.py more complicated and letting other scripts import it's pieces, we've made a `clubb_case_runner`.
    
    `clubb_case_runner` is a python object that abstracts the backend decisions. The "flow" is roughly:
    - high level script wants to run a clubb case some how
    - generates one or more case namelists (arm.in, bomex.in, etc)
    - creates a `clubb_case_runner` by passing it whatever runtime options (-jax/-python/-exe) the user requested
    - runs a case by passing this `clubb_case_runner` whatever namelists it wants to run.
    
    In addition to deduplicating runtime setting logic, this allows python scripts to create these high level `clubb_case_runner` objects and use those to do things that usually requires duplicate multiprocessesing and error code parsing logic.
